# Specification: Group Settings since 94-resumable

Compare `suu/issue-94-resumable-downloads` (`b005de1fcaa58de298f9bd666e4e8f38571454c8`) to the captured `suu/group-settings` checkout (`22d0bf1db3cf5f14efecfb65364717658668b9a3` plus tracked edits). The base is the merge base and predates Configuration Packages. The tracked diff includes 52 paths and covers the station, console, Android application, Wi-Fi recovery, service startup, permissions, tests, and documentation. The untracked local `uv.lock`, previous rebuild documents, previews, and field evidence are source material or local tooling, not applied source changes. No live registry or device data was copied.

The requirement sources are the November 9 and 10 decisions and validation notes in [tasks/todo.md](../../../tasks/todo.md), [engineering lessons](../../../tasks/lessons.md), the [developer guide](../../DEVELOPMENT.md), [Wi-Fi guide](../../WIFI_SETTINGS.md), and the earlier [rebuild record](../VERIFY.md). The original recipe and complete conversation are unavailable. Later decisions supersede older ones: Save & deploy and group Deploy are combined operations in the console; manual Reapply uses a persistent last-received policy. Existing draft/save/publish routes remain supported. The repository contains test fixtures and prior PUI 5.15.7 / ToB 4.3.30 observations, not a qualification of every model and firmware.

The current screen offers short delay options that were reported unsupported on the observed firmware (sleep 15/30/60 seconds; screen-off 3/10 seconds read back as 30). The November 10 audit recorded no saved/deployed use of these values in its checked registry. This is a firmware/catalog mismatch to address with a firmware-specific acceptance decision, not an acceptance criterion to silently relax here.

The public PICO docs were consulted through Context7 using `/websites/business_picoxr_us_doc`. The [PICO Enterprise SDK reference](https://business.picoxr.com/us/doc/EnterpriseAPI-Intro) covers SDK and Device Owner restrictions; [Android Wi-Fi API documentation](https://developer.android.com/reference/android/net/wifi/WifiManager#getConfiguredNetworks()) gives platform limits. They do not establish PUI-specific delay behavior or hardware parity.

### Evaluation probes

1. Two consoles edit membership. Delay the remote snapshot on one; move an untouched device to a group with a different published value and save another addition. Then submit an explicitly stale move. Compare exact device delivery and what the UI reports.
2. In one group use No package, in another deploy a shared package with offline members and a same-size change between preview and commit. Fail the registry replacement and simulate reconnect. Compare committed state, response, and effective policy.
3. Lose the process at a Wi-Fi handoff boundary; reconnect or manually Reapply offline after restart. Compare scalar/Wi-Fi call counts, retained evidence, cache clearing, and bounded content startup. The tests model host callbacks, not firmware behavior.
